# AI On-Call — план проекта

Рабочее название: **Incident Lab**. Публичный сайт, где посетитель ломает настоящий сервер,
а AI-дежурный инженер вживую расследует, чинит и пишет постмортем.

Статус: **черновик, ждёт одобрения**. Код пока не пишем.

---

## 1. Что видит посетитель

1. Открывает `samsarukhanyan.com` и видит живую схему системы: сервер, nginx, релизы, диск, CPU.
   Всё зелёное, графики обновляются раз в несколько секунд.
2. Нажимает **«Сломай»** и выбирает поломку из списка или «Удиви меня». В режиме «Удиви меня»
   агент **не знает**, что сломано, и видит только симптомы.
3. Экран делится на панели, все обновляются в реальном времени:
   - **Таймлайн**: тревога → расследование → действие → проверка → решено;
   - **Мысли агента**: «Гипотеза 1: nginx не запущен. Проверяю…»;
   - **Терминал** (только чтение): команды, которые агент выполнил, и их вывод;
   - **Метрики**: здоровье сайта, диск, CPU, время ответа.
4. Сайт снова зелёный. Показываются время до починки, стоимость в токенах и **постмортем**.
5. Все инциденты сохраняются в публичный архив `/incidents`, каждый со своей ссылкой,
   чтобы ей можно было поделиться.

Если агент не справился за 5 минут, система **честно** пишет «агент не справился»
и откатывает песочницу скриптом. Это тоже показатель профессионализма.

---

## 2. Главный принцип безопасности

> Посетитель **никогда** не трогает продакшн. Агент **никогда** не выполняет произвольные команды.

- Ломается **отдельный сервер-песочница** (`lab`), а не сервер с сайтом.
- Агент действует только через **заранее описанные инструменты**. Каждый инструмент — это
  SSM-документ с фиксированной командой и проверкой параметров, как наш `portfolio-deploy`.
- Роль IAM для агента может отправлять команды **только** на песочницу и **только**
  через эти документы. Даже если модель «сойдёт с ума», сломать прод или AWS она не сможет.
- Посетители не получают shell. Терминал на сайте — это только трансляция того, что сделал агент.
- Лимиты: одновременно идёт один инцидент (остальные в очереди), у каждого IP есть
  пауза между поломками, есть дневной лимит инцидентов и месячный лимит денег на AI.

## 3. Архитектура

```
 Браузер ──HTTPS──► nginx (prod EC2, уже есть)
   │                 ├── /            React-сайт (статика, как сейчас)
   │                 └── /api, /events ─► Control Plane (Node + TypeScript, systemd)
   │                                        │  ├─ API: сломать, статус, инциденты
   └──── SSE (поток событий) ◄──────────────┤  ├─ Event store (JSONL)  
                                            │  ├─ Health prober (каждые 5 с)
                                            │  └─ Agent runner ──► Claude API
                                            │
                                            └── AWS SSM (только allowlist-документы)
                                                     ▼
                                           Lab EC2 (песочница, новая)
                                             nginx + демо-приложение + релизы
                                             chaos-скрипты, reset-скрипт
```

| Компонент | Технология | Почему так |
|---|---|---|
| Сайт | React 19 + Vite + TS (уже есть) | переиспользуем; деплой уже готов |
| Живой поток | **SSE** (Server-Sent Events) | поток идёт в одну сторону (сервер → браузер), это проще WebSocket и легко проходит через nginx |
| Терминал на сайте | xterm.js, только чтение | выглядит как настоящий терминал |
| Control Plane | Node + TypeScript, Express (уже есть в `server/`) | тот же язык, что и на фронте; без новых библиотек; работает как служба systemd на prod EC2 |
| Хранилище | файлы JSON/JSONL (`LAB_DATA_DIR`) | один сервер, несколько инцидентов в день: ноль зависимостей и администрирования, бэкап через снимки EBS |
| AI | переключатель провайдера: Claude Haiku 5.5 (сайт) или Ollama (разработка), см. раздел 3.1 | агент сам решает, какой инструмент вызвать; модель меняется одной настройкой |
| Секреты | AWS SSM Parameter Store (SecureString) | API-ключ не хранится ни в коде, ни в GitHub |
| Инфраструктура | Terraform (уже есть) | новая песочница, IAM, SSM-документы, поддомен |
| Мониторинг продукта | UptimeRobot (есть) + бюджет AWS + лимит в Anthropic Console | |

### 3.1 AI-провайдеры (переключатель)

Код агента один. Модель подставляется через небольшой интерфейс `ModelProvider`
(«вот история и инструменты → верни ответ или вызов инструмента»):

```
AI_PROVIDER=claude   # сайт для посетителей: Claude Haiku 5.5 через Claude API, работает 24/7
AI_PROVIDER=ollama   # разработка на ноутбуке: локальная модель, бесплатно
```

| | `claude` (продакшн) | `ollama` (разработка) |
|---|---|---|
| Где работает | API в интернете, вызывается из Control Plane | ноутбук, `localhost:11434` |
| Цена | ~$0.005 за инцидент | $0 |
| Доступность | всегда | только когда ноутбук включён |
| Модель | Claude Haiku 5.5; если evals покажут < 90%, сложные случаи отдаём Sonnet 5.5 | Qwen 3.5 / Gemma 4, выбор по замеру на ноутбуке |

Отдельный AI-сервер в AWS **не нужен**.

**Экономия токенов** (обязательно с первого дня):
1. Prompt caching для системного промпта и описаний инструментов.
2. Перед агентом бесплатный скрипт собирает «анализы» (health, диск, статус служб, хвост логов)
   и передаёт их в первом сообщении. Так агенту нужно меньше шагов.
3. Инструменты возвращают коротко: десятки строк, а не тысячи.
4. Старые результаты инструментов вычищаются из истории.
5. Низкий effort; лимит 10 шагов на инцидент.
6. Режим повтора записанных инцидентов: 0 токенов.
7. Дневной лимит живых инцидентов и жёсткий месячный лимит в консоли API ($5).

### Поломки (chaos-сценарии), первая версия

У каждого сценария есть три скрипта: **сломать**, **проверить, что починено** (oracle)
и **сбросить**. Агент oracle не видит.

| # | Поломка | Что видит агент | Правильная починка |
|---|---|---|---|
| 1 | nginx остановлен | сайт не отвечает | `restart_service nginx` |
| 2 | диск забит | 500, «No space left» в логах | найти и удалить мусорный файл (только в разрешённых путях) |
| 3 | плохой релиз | белый экран, JS-ошибка | `rollback` на прошлый релиз |
| 4 | сломан конфиг nginx | nginx не стартует | `nginx -t` → откат конфига → PR с исправлением |
| 5 | процесс съел CPU | сайт отвечает медленно | найти и остановить процесс |

Позже: упала база, кончился сертификат, утечка памяти, несколько поломок сразу.

### Инструменты агента (allowlist)

Для чтения: `check_health`, `get_metrics`, `read_logs(service, lines)`, `list_releases`,
`disk_usage(path)`, `list_processes`, `nginx_config_test`, `recent_changes`.

Для действий: `restart_service(name ∈ {nginx, app})`, `rollback(release)`,
`delete_file(path ∈ /var/lab/**)`, `kill_process(pid, только процессы демо-приложения)`,
`restore_config(name)`, `open_pull_request(...)`, `resolve(summary)`.

Каждое действие пишется в таймлайн и в постмортем.

## 4. Команда (роли)

Работаем как маленькая команда. **Я, основная сессия, — техлид**: держу этот план и
контракты, раздаю задачи, проверяю результат и говорю с вами. Остальные роли — субагенты
с узкой зоной (`.claude/agents/*.md`). Каждый работает **только в своих папках**.

| Роль | Зона (папки) | Отвечает за |
|---|---|---|
| **Tech Lead** (основная сессия) | `docs/ai-oncall/`, `contracts/` | план, контракты, ревью, интеграция, общение с вами |
| **Infra** | `infra/` | песочница, IAM, SSM-документы, поддомен, бюджеты |
| **Chaos** | `lab/` | демо-приложение, скрипты поломок, oracle, reset |
| **Backend** | `server/` | Control Plane: API, SSE, хранилище, лимиты, health prober |
| **Agent** | `server/src/agent/` | промпт, инструменты, цикл агента, оценки (evals) |
| **Frontend** | `client/` | живая консоль, архив инцидентов, лендинг |
| **QA / Security** | только чтение + `tests/` | модель угроз, проверка изоляции, end-to-end тесты |

### Правила, чтобы не тратить токены и не делать лишнего

1. **Сначала контракты, потом код.** Схема событий, API и список инструментов фиксируются
   в `contracts/` до того, как роли начинают писать код. Роли общаются через контракты,
   а не через пересказы.
2. **Одна задача — одна роль — один чёткий результат.** В задаче указаны: файлы, критерий
   готовности и что **не** трогать.
3. **Субагента запускаем только для большой задачи.** Мелкие правки техлид делает сам:
   субагент каждый раз стартует «с нуля» и заново читает контекст, а это дорого.
4. **Минимум кода.** Без лишних библиотек, абстракций «на будущее» и генераторов.
   Если решение не нужно для текущего этапа, его нет.
5. **Каждый этап заканчивается проверкой вживую**, а не «в теории»: сломали → увидели →
   починили.
6. **Нет зелёного QA — нет мержа.**

### Ход каждой задачи

```
Tech Lead: задача + ссылки на контракт
   → Роль: реализация в своих папках, без коммита
   → QA/Security: ревью и тесты
   → Tech Lead: проверка, интеграция, коммит
   → вы: смотрите вживую и одобряете
```

## 5. Этапы

Каждый этап можно показать и проверить. После каждого этапа вы одобряете следующий.

| Этап | Результат, который вы увидите | Роли |
|---|---|---|
| **0. Контракты** | `contracts/`: события, API, инструменты, сценарии | Tech Lead |
| **1. Песочница** | `lab.samsarukhanyan.com` работает отдельно от сайта; `terraform plan` чистый | Infra |
| **2. Поломки без AI** | каждая поломка ломает, oracle видит поломку, reset возвращает всё как было (5/5) | Chaos, QA |
| **3. Control Plane + фейковый агент** | кнопка «Сломай» работает, события идут в браузер по SSE, роль агента пока играет скрипт | Backend, Frontend |
| **4. Живая консоль** | таймлайн, мысли, терминал, метрики: красиво и в реальном времени | Frontend |
| **5. Настоящий AI-агент** | Claude чинит все 5 поломок; прогон оценок (evals): процент успеха, время, стоимость | Agent, QA |
| **6. Постмортемы и PR** | архив `/incidents`, ссылки, настоящие PR в демо-репозитории | Agent, Backend, Frontend |
| **7. Запуск** | лимиты, защита от злоупотреблений, документация, новый лендинг | все, QA |

**Цель по качеству перед запуском (этап 5):** агент чинит **≥ 90%** инцидентов
в среднем **< 2 минут**, и ни одного действия вне allowlist.

## 8. Как это вырастет в продукт

Демо → open-source «агент + allowlist-инструменты» → SaaS «AI on-call» для маленьких команд:
подключение своего сервера через SSM, Slack-уведомления, режим «спросить человека перед
действием», общая база постмортемов. Песочница из демо становится **тренажёром**, на котором
агента проверяют перед тем, как пустить на прод клиента.
