# YOLO Studio — dev-стенд Ultralytics YOLO

Отдельный проект для экспериментов с Ultralytics YOLO: камера и видео в браузере → распознавание
всех задач YOLO → сбор и разметка своих данных → дообучение → проверка своей модели снова на камере.

```
React (Vite, :5180) ──/api────▶ Node.js + Express (:4010) ──▶ MySQL (yolo_studio)
        │                               │
        └──/vision (HTTP + WebSocket)──▶ Python FastAPI + Ultralytics + PyTorch (:8001)
        └── ONNX Runtime Web (WebGPU / WASM) — второй движок прямо в браузере
```

| Часть | Что делает |
|---|---|
| `vision/` (Python) | Инференс по WebSocket, трекинг, задачи в фоне: обучение, валидация, экспорт, скачивание моделей |
| `api/` (Node) | Датасеты, фото, разметка, запуски обучения, журнал сессий камеры — всё в MySQL; собирает датасет в формат YOLO |
| `web/` (React) | Вкладки «Камера», «Датасеты» (редактор рамок), «Обучение» (графики), «Модели» (каталог, экспорт), «Система» |
| `data/` | Веса, датасеты, результаты обучения, экспорты (в git не попадает) |

## Что уже встроено

- **Все задачи YOLO26 / YOLO11 / YOLOv8:** детекция, сегментация, позы (скелет), повёрнутые рамки (OBB),
  классификация, семантическая сегментация, карта глубины. Размеры n/s/m/l/x скачиваются при первом выборе.
- **Открытый словарь:** YOLOE-26 и YOLO-World ищут то, что вы впишете словами (по-английски);
  YOLOE-26 «-pf» распознаёт ~4500 классов без подсказок. Также Open Images V7 (600 классов), RT-DETR, FastSAM.
- **Трекинг** ByteTrack / BoT-SORT: ID объектов, траектории, подсчёт уникальных объектов по классам.
- **Источники:** веб-камера (выбор камеры, зеркало), видеофайл, фото.
- **Настройки:** conf, iou, imgsz, max_det, фильтр классов, TTA, NMS без учёта класса.
- **Два движка с замером скорости:** Python-сервер и браузер (ONNX). Таблица «Сравнение движков» показывает FPS обоих.
- **Сбор данных:** снимок с камеры в датасет (с авторазметкой текущей моделью), автосъёмка раз в 1/2/5 с,
  загрузка фото с авторазметкой.
- **Разметка:** рамки мышью, классы клавишами 1–9, Delete, ←/→, Ctrl+S, разбиение train/val.
- **Обучение** из интерфейса: прогресс по эпохам и батчам, графики mAP и потерь, PR-кривые, матрица ошибок;
  «Открыть в камере», валидация, экспорт.
- **Экспорт:** ONNX (для браузера), TorchScript, OpenVINO, NCNN.

## Запуск

Один раз:

```bash
npm run setup            # venv + PyTorch CPU + Ultralytics, npm-пакеты, api/.env
./scripts/setup-db.sh    # создаёт базу и пользователя MySQL (спросит пароль sudo)
```

Каждый раз:

```bash
npm run dev              # vision :8001 + api :4010 + web :5180
```

Откройте http://localhost:5180 → «▶ Камера». Камера в браузере работает только на localhost или https.

### С телефона (iPhone / Android в той же Wi-Fi сети)

```bash
npm run phone            # то же самое, но сайт открыт в локальную сеть по HTTPS на порту 5443
```

На телефоне откройте `https://<IP компьютера>:5443` (IP: `ip -4 addr`, обычно 192.168.x.x).
Сертификат самоподписанный: в Safari «Показать подробности» → «посетить этот веб-сайт» → «Посетить веб-сайт».
Затем выберите «Задняя (телефон)» или «Передняя (телефон)» и нажмите «▶ Камера».
Наружу открыт только Vite; Python и Node слушают 127.0.0.1. Пароля у стенда нет, запускайте только в доверенной сети.
Если телефон не подключается и включён ufw: `sudo ufw allow 5443/tcp`.

## Как обучить свою модель

1. «Датасеты» → создайте датасет (детекция / сегментация / классификация) и классы.
2. «Камера» → выберите датасет внизу → «📸 Снимок в датасет» (или автосъёмка). С авторазметкой текущая модель
   ставит черновые рамки; новые имена классов добавляются сами.
3. «Датасеты» → откройте фото и поправьте рамки. Часть фото пометьте как `val`
   (если не пометить, каждое 5-е фото уйдёт в val; при < 10 фото val = train).
4. «Обучение» → датасет, базовая модель (`yolo26n.pt`, для классификации `yolo26n-cls.pt`) → «Обучить».
   На CPU разумно начинать с imgsz 320 и 30–50 эпох.
5. «Открыть в камере» — ваша модель появится в группе «Ваши обученные».

## Скорость на этом ноутбуке (Ryzen 7 5800HS, без GPU)

| | yolo26n, 640px |
|---|---|
| Python-сервер, PyTorch, 8 потоков | ~47 мс инференс (~20 FPS с учётом передачи кадра), 320px — ~23 мс |
| Браузер, ONNX Runtime WASM × 8 | ~80 мс на кадр |

Поэтому по умолчанию работает сервер. В Chrome с WebGPU браузерный движок может оказаться быстрее —
сравните на вкладке «Камера».

## Заметки

- Число потоков PyTorch: `STUDIO_THREADS` (по умолчанию половина логических ядер). Ultralytics при импорте ставит
  `OMP_NUM_THREADS=1`, поэтому без этой настройки работает одно ядро.
- Отправка анонимной статистики Ultralytics отключена (`sync: false`). Папки весов/запусков/датасетов в
  `~/.config/Ultralytics/settings.json` указывают на `yolo-studio/data`.
- Первый запуск YOLO-World скачивает CLIP (338 МБ), YOLOE — MobileCLIP (254 МБ); дальше они берутся из `data/models`.
- Лицензия Ultralytics — AGPL-3.0: для закрытого коммерческого продукта нужна их коммерческая лицензия.
